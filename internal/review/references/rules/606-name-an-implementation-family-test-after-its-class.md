# 606: Name a Test for One of a Family of Implementations After Its Class, Not Its Behavior

When a test exercises one implementation from a family of sibling implementations of a shared interface or abstract type (an `ObjectActionExecutor`, an `MVCActionCommand`, an `UpgradeStep`, and the like), name the test class after that implementation class — dropping only the `Impl` suffix — never after the business behavior it happens to exercise. A behavior-based name does not say which implementation's interface method is under test; a reader has to open the file to find out, and two implementations with similar behavior (`ComputeNextScanDate...` vs. some other date-computing action) become impossible to tell apart by class name alone.

**Rationale:** A family of implementations already has one axis of truth for what a member does — its own class name. A test class that restates the behavior in different words (`ComputeNextScanDateSEOStudioTest` for `ComputeSEOStudioDomainNextScanDateObjectActionExecutorImpl`) creates a second, looser name for the same thing, and the mapping from a failing test back to the class it tests stops being mechanical. This is rule [603] (name a test after the method it tests) applied one level up, to the class that owns the interface method, for exactly the case where many sibling classes implement that same method.

A violation is a test class for one member of an interface-implementation family whose name describes what the code does instead of which implementation class it tests. This most often appears when a developer consolidates shared setup across the family into a common base test case and, in the same change, shortens each subclass's name to a behavioral one instead of keeping the implementation-matching name.

**Grep recipe:** `git ls-files '*<Interface>.java'` or the family's naming pattern (e.g. `git ls-files '*ObjectActionExecutor.java'`) enumerates the implementation family; confirm each has a `git ls-files '*<Interface>Test.java'` sibling whose prefix matches the implementation class, not a shortened behavioral name.
